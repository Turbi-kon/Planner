# Лист — ежедневник

Небольшое настольное приложение на **Python 3.10+ / PySide6 / SQLite**. Интерфейс и сообщения на русском.

## Запуск

Готовый **ListPlanner.exe** можно запускать на другом компьютере с Windows 10 (1809+) / Windows 11 x64. Python, PySide6 и SQLite на этом компьютере устанавливать не нужно. EXE содержит библиотеки и SQL-схему; база создаётся автоматически при первом запуске в папке данных текущего пользователя. Для переноса достаточно самого EXE.

Ниже — запуск из исходников; он нужен для разработки.

На Windows: распаковать архив и открыть **run.bat**. При первом запуске он создаст локальное окружение `.venv` и установит PySide6 (нужен интернет). Нужен заранее установленный Python с Python Launcher (`py`).

Или из терминала в папке проекта:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

На Linux/macOS вместо `.\.venv\Scripts\python.exe` используйте `.venv/bin/python`.

SQLite отдельно устанавливать не нужно: приложение использует модуль `sqlite3` из стандартной библиотеки Python. Таблицы создаются автоматически из `planner/schema.sql`. В архиве нет готовой базы с личными данными.

## Сборка EXE

На компьютере разработчика нужен Windows и 64-разрядный Python (проверено на Python 3.12). Откройте **build_exe.bat**: он установит зависимости и PyInstaller в локальное окружение `.venv`, затем создаст **dist/ListPlanner.exe**. Администраторские права не нужны. Готовый файл запускается без консольного окна.

Или вручную:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-build.txt
.\.venv\Scripts\python.exe build_exe.py
```

SQL-файл включается в сборку явно через `--add-data`. Модули `sqlite3`, Python и Qt попадают в EXE вместе с приложением. Личная база, настройки Telegram и содержимое `.venv` в сборку не добавляются. Рабочая база хранится отдельно от EXE, поэтому обновление программы не стирает записи. Режим `onefile` распаковывает библиотеки во временную папку при запуске; первый запуск может занять несколько секунд.

Для переноса **записей и настроек** на другой компьютер завершите приложение на обоих ПК и перенесите `planner.sqlite3` в папку данных приложения на новом ПК. Просто копирование EXE создаёт отдельную пустую базу на новом компьютере.

Пример явного выбора папки базы для EXE:

```powershell
.\ListPlanner.exe --data-dir "D:\MyPlannerData"
```

Сборка `.exe` предназначена для Windows x64. Для macOS/Linux нужно собирать отдельные приложения на соответствующей ОС; Windows EXE там нативно не запускается. См. [описание PyInstaller](https://pyinstaller.org/en/stable/operating-mode.html) и [поддерживаемые платформы Qt 6.8](https://doc.qt.io/qt-6.8/supported-platforms.html).

## Что умеет

- Добавление, редактирование и удаление записей; поиск по названию и заметке.
- Серая тема по умолчанию; белая и тёмная выбираются кнопкой «Настройки» → вкладка «Оформление» → «Тема приложения» → «Сохранить». Оформление меняется без перезапуска и сохраняется в базе. Тема применяется также к календарю, меню и диалогам.
- Фильтры: сегодня, предстоящие, прошедшие, дни рождения.
- Дата, время и напоминание в момент события, за 5/15/30 минут, час или день.
- Напоминания отдельным немодальным окном поверх других обычных окон (`WindowStaysOnTopHint`); кнопка проверки в главном окне. Напоминание не исчезает по таймеру: «Понятно» или крестик закрывают его, «Открыть ежедневник» открывает главное окно. Новые напоминания добавляются в уже открытое окно, предыдущие сохраняются в его списке.
- Дни рождения повторяются ежегодно. Для 29 февраля в обычный год используется 28 февраля; год в поле даты может быть годом рождения.
- Отправка в Telegram через HTTPS `sendMessage`. API-ключ и ID чата / группы задаются в «Настройки» → «Телеграм-бот»; там же есть «Отправить тестовое сообщение». Ключ скрыт в поле ввода. Канал «В Telegram» включается отдельно для каждой записи.
- Очистка старых обычных записей при первом запуске, затем раз в **шесть календарных месяцев**. Дни рождения не удаляются.

Крестик закрытия сворачивает программу в системный трей, если он доступен. Открытие: нажать значок в трее. Полный выход: меню значка → «Завершить работу». Если трея нет, закрытие окна завершает приложение.

**Программа должна оставаться запущенной для напоминаний.** Автозапуск с Windows и отдельная фоновая служба пока не добавлены. Во время сна или выключения ПК программа не работает; после пробуждения / запуска проверяет напоминания снова. Расписание использует местное время компьютера. Всплывающее окно работает также при скрытом в трее главном окне и не использует системные баннеры уведомлений. Поверхность защищённого рабочего стола Windows (например, UAC) и исключительный полноэкранный режим управляются самой ОС.

## Правила напоминаний и очистки

Локальные напоминания проверяются при запуске и каждые 10 секунд. Для локального канала передаётся максимум одно напоминание за проверку; остальные добавляются в открытое окно при следующих проверках. Очередь Telegram проверяется каждую секунду: HTTP-запросы выполняются по одному в рабочем потоке с таймаутом 15 секунд. Чтение/запись SQLite выполняется в главном потоке.

Обычная запись напоминает один раз, когда наступит время напоминания. Если программа была закрыта, напоминание приходит при следующем запуске, если запись ещё не удалена плановой очисткой. Прошлые дни рождения не догоняются: только сегодняшний или ближайший будущий день рождения с уже наступившим временем напоминания.

Для каждого канала сохраняется факт передачи уведомления. Он переживает перезапуск; изменение заметки или названия не вызывает повторную отправку. Изменение даты, времени или интервала напоминания сбрасывает отметки для этой записи. Подтверждение локального канала означает добавление напоминания во всплывающее окно, а не подтверждение прочтения человеком. Если процесс аварийно завершится между показом и сохранением отметки, возможно повторное уведомление.

Очистка сравнивает **даты**, а не часы: удаляет `event_date < сегодня AND is_birthday = 0`. Сегодняшние записи сохраняются. Следующая дата очистки хранится в базе, закрытие программы её не сбрасывает. Если приложение долго не запускали, просроченная очистка выполняется при запуске, следующая назначается через полгода от фактической проверки. Срок считается календарными месяцами: 31 августа → 28/29 февраля. Сначала выполняется очистка, затем проверка напоминаний.

## Где лежат данные

Обычный запуск сохраняет данные в пользовательской папке приложения Qt `AppLocalDataLocation`: на Windows обычно `%LOCALAPPDATA%\ListPlanner\ListPlanner`.

- `planner.sqlite3` — основная база;
- `planner.sqlite3-wal` / `planner.sqlite3-shm` — служебные файлы SQLite во время работы;
- `planner.log` — журнал ошибок с ограничением размера;
- `planner.lock` — блокировка второго запуска с той же базой.

Можно явно выбрать папку:

```powershell
python main.py --data-dir ./data
```

Для копирования базы полностью завершите приложение через трей и скопируйте `planner.sqlite3`. Плановая очистка удаляет записи без корзины; при необходимости заранее сохраняйте резервные копии.

## Схема базы

| Таблица | Назначение |
| --- | --- |
| `events` | Название, заметка, дата/время, признак дня рождения, интервал и каналы |
| `notification_deliveries` | Факт отправки по записи, дате повторения и каналу; уникальный ключ защищает от повторной отправки после перезапуска |
| `app_settings` | Выбранная тема, API-ключ Telegram, ID чата / группы, даты следующей и последней очистки |

Удаление записи каскадно удаляет её отметки отправки. SQL-запросы параметризованы. Схема помечена `PRAGMA user_version = 4`; изменения будущих версий требуют миграций.

## Подключение Telegram

1. Создайте бота через BotFather и скопируйте его токен.
2. Для личного чата откройте своего бота в Telegram и нажмите **Start / /start**. Для группы добавьте в неё бота с правом отправки сообщений.
3. Откройте «Настройки» → **«Телеграм-бот»** и введите API-ключ и ID чата / группы. Можно использовать отрицательный ID группы или `@username` публичной супергруппы / канала; для канала нужны права публикации.
4. Нажмите **«Отправить тестовое сообщение»**. Проверка использует введённые поля, даже если они ещё не сохранены, и показывает результат прямо во вкладке.
5. Нажмите **«Сохранить»**. У нужной записи включите **«В Telegram»** и сохраните запись.

Настройки переживают перезапуск; «Отмена» не сохраняет изменения. Чтобы отключить канал целиком, очистите оба значения и сохраните. Проверка подключения отправляет отдельное тестовое сообщение и не меняет отметки доставки событий.

Токен хранится в локальной SQLite-базе **без шифрования**; маскирование относится к полю ввода. Ключ не записывается в журнал и не включается в архив исходников. При передаче личной базы другому человеку учитывайте, что в ней есть эти настройки.

HTTP-клиент — `planner/telegram_api.py`, фоновая очередь — `planner/telegram_dispatcher.py`. Сообщение считается отправленным только после `ok: true` и ответа с `message_id`; при ошибке отметка не ставится, повтор выполняется через минуту. Для ограничения частоты учитывается `retry_after` от Telegram. Ошибки ключа, чата, прав и сети показываются в окне; статус записи меняется на «TG: ошибка» или «TG: отправлено». Сырые URL и токены не выводятся в сообщения ошибок.

Если событие удалено, перенесено или получатель изменён во время запроса, ответ старого запроса не помечает новую версию события доставленной. Уже начатый HTTP-запрос отменить нельзя. В случае разрыва связи после приёма сообщения сервером, но до получения подтверждения, при повторной попытке возможен дубль: Bot API не предоставляет ключ идемпотентности для `sendMessage`.

Для Telegram нужны интернет и работающая программа. Уведомления не отправляются, пока компьютер выключен или приложение полностью закрыто. Требования к боту и API: [Telegram Bot API](https://core.telegram.org/bots/api#sendmessage), [Telegram Bots](https://core.telegram.org/bots/features#botfather).

## Демонстрация и проверки

Примеры добавляются **только по явному флагу** в пустую базу, с выключенными системными уведомлениями:

```powershell
python main.py --demo --data-dir ./demo-data
python -m unittest discover -s tests -v
```

Тесты ядра не требуют PySide6. Проверяют SQLite, календарь, HTTP-запросы и ошибки Telegram, фоновую отправку, подтверждение доставки, повторы, изменение получателя и удаление записи во время запроса. Транспорт в тестах подменён: сообщения реальным людям тесты не отправляют.

Исходные API: [sqlite3 / Python](https://docs.python.org/3/library/sqlite3.html), [QSystemTrayIcon / Qt for Python](https://doc.qt.io/qtforpython-6/PySide6/QtWidgets/QSystemTrayIcon.html).

## Формат Telegram и дни рождения

Обычная запись отправляется в таком порядке, без служебных префиксов:

```text
Название заметки
20.10.2026 18:30
Текст заметки
```

Для записи с тегом «День рождения»:

```text
Алексей
20.10.2026 10:00
25 лет — юбилей
Поздравление, составленное из списков фраз
```

Вместо названия используется поле «Имя именинника». Если имя не заполнено, оно берётся из названия без начального «День рождения». Заметка к дню рождения не добавляется в Telegram-поздравление. Если год рождения неизвестен, строка возраста пропускается полностью. Возраст считается для даты ежегодного повторения; 18 лет отмечается как совершеннолетие, возраст от 20 лет, кратный пяти, — как юбилей. Склонения работают и для 21 года, 23 лет в форме «23 года», 111 лет.

Стиль поздравления выбирается в форме дня рождения: тёплый, шуточный или для программиста. В каждом стиле пять блоков по четыре варианта: начало, поздравление, пожелание, дополнительная фраза и финал. Это 1024 сочетания на стиль.

Готовый текст не вводится и не сохраняется. Выбор фраз и сборка поздравления выполняются рабочим потоком прямо перед HTTP-запросом в Telegram. При следующей отправке фразы выбираются заново. Время отправки определяется полями даты, времени и интервала напоминания; для поздравления непосредственно в праздник выберите «В момент события».

На компьютере показывается только обычное напоминание: название, дата/время и заметка. Поздравление не генерируется при сохранении записи, просмотре формы или показе всплывающего окна. В форме остаются имя, необязательный год рождения, стиль и краткая информация о ближайшем повторении.

Отдельное поле «Текст сообщения для Telegram» и ручной конструктор удалены. Старое поле `telegram_text` в существующей базе сохраняется для совместимости и сохранности данных, но не читается и не участвует в отправке. При обновлении старой базы добавляется `greeting_style`, версия схемы становится 4. Записи, настройки, годы рождения и отметки доставки сохраняются.

Telegram принимает текст до 4096 символов. Обычная заметка вместе с названием и датой должна укладываться в этот лимит; слишком длинное сообщение вызывает понятную ошибку и не обрезается молча.
